② 相机空间（View）V·M·v

相机被移到原点、朝 −Z 看：视锥就是原点伸向 −Z 的棱台。可见物体 z < 0。

③ 裁剪 / NDC 空间÷w

透视除法把视锥棱台压成 [−1,1]³ 立方体；红点 = 越出裁剪空间、将被裁剪的顶点。

④ 屏幕像素（Viewport）视口变换 + 真实裁剪

图元在裁剪空间做 Sutherland–Hodgman 裁剪后除 w、映射像素，y 翻转（画布 y 向下）。

深度为什么非线性zndc 随 zview 的映射

透视矩阵的 z 列含 1/z 项：近处斜率陡、远处平缓——深度缓冲的精度集中在近处，远处容易 z-fighting；near 取得过小会指数级恶化。工程上常用 reversed-Z + 浮点深度缓冲 缓解（[0,1] 深度的 DirectX 上做 reversed-Z 更自然）。正交投影没有 ÷w，深度保持线性。

经典简答 · 逐题自测

点击展开答案；每一条都能在本页的视图与矩阵里找到对应的可视化证据

连续变换为什么写成 P·V·M·v？顺序能换吗？
列向量右乘时矩阵从右往左作用：先 M 把物体从局部空间摆到世界空间，再 V 变换到相机空间，最后 P 投影到裁剪空间。矩阵乘法不满足交换律，顺序不可换——「先投影再旋转」得到的结果完全不同。若采用行向量约定（DirectX 常用），则写作 v·M·V·P，顺序镜像；两种约定混用是变换结果出错的头号原因。
w 分量有什么用？为什么 w ≤ 0 必须裁剪？
w 有两个职责：① 裁剪基准——图元必须满足 −w ≤ x, y, z ≤ w（视锥的四棱锥不等式）；② 透视除法的分母——x/w、y/w、z/w 把四棱锥压成 [−1,1]³ 立方体。透视矩阵第四行 (0,0,−1,0) 使 w = −zview，恰好携带「顶点离相机多远」的透视信息；w ≤ 0 意味着顶点在相机之后或无穷远，除法无几何意义，必须先裁剪。
为什么 OpenGL 选右手系 + 相机朝 −Z？DirectX 的选择错了吗？
没有对错，只有自洽。右手系下 x×y=z，与「相机空间 X 右、Y 上、Z 从屏幕指向观察者」配合，叉积求出的法线、CCW 绕序定义的正面全部自洽。DirectX 常用左手系 + 朝 +Z，等效于把世界镜像，投影矩阵随之换号——只要公式与约定配套，渲染结果可以完全一致。本页全部推导严格按 OpenGL 约定，若移植到 DirectX 需逐项镜像。
透视投影和正交投影的矩阵差别到底在哪一行？
在第四行和 z 列：透视矩阵第四行是 (0, 0, −1, 0)，使 w′ = −zview ≠ 常数，透视除法产生「近大远小」，平行线相交于消失点；z 列还带 1/z 项使深度非线性。正交投影第四行是 (0, 0, 0, 1)，w′ 恒为 1，除法是恒等运算——平行线保持平行，深度线性。切换本页「正交投影」开关可直观对比两个面板的形状与深度曲线。
near 平面调小会发生什么？为什么？
透视深度 zndc = (f+n)/(f−n) + 2fn/((f−n)·zview)，n→0 时曲线在 near 附近斜率爆炸：深度缓冲的精度几乎全部堆在近处，远处两个表面深度值接近到无法区分，产生 z-fighting。near 应在「不切穿最近物体」前提下尽量取大。下方深度曲线拖动 near 滑块即可看到曲线越来越弯。
